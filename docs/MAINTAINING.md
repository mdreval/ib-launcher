# Igrobar Launcher — для разработчика

Всё, что нужно владельцу проекта: запуск из исходников, выпуск версий,
настройка сервера IGROBAR, устройство лаунчера. Витрина для игроков — в [README](../README.md).

## Запуск из исходников

```bash
npm install
npm start
```

Если `npm install` пишет `install scripts not yet covered by allowScripts` для
electron — бинарник Electron кладётся вручную: содержимое
`electron-v32.x.x-win32-x64.zip` → `node_modules\electron\dist` и файл
`node_modules\electron\path.txt` с текстом `electron.exe`.

## Выпуск новой версии (GitHub Actions)

Версия лаунчера задаётся в **одном месте** — `data/server_profiles.json`, поле
`"launcher_version"` (сейчас `2.0.0`). В `package.json` её переносит скрипт
`scripts/sync-version.js` — сам, перед `npm start`, `npm run dist` и в GitHub Actions.
Руками `package.json` менять не нужно.

1. Залейте проект в репозиторий GitHub. Имя репозитория — в `package.json`
   → `build.publish` (сейчас `mdreval/ib-launcher`).
2. Поменяйте `"launcher_version"` в `data/server_profiles.json`, например на `2.0.1`.
3. Отправьте на GitHub:
   ```bash
   git add .
   git commit -m "Лаунчер 2.0.1"
   git push
   ```
4. Workflow `.github/workflows/release.yml` увидит, что релиза `v2.0.1` ещё нет, и соберёт:
   - `Igrobar-Launcher-Setup-2.0.1.exe` — установщик Windows;
   - `Igrobar-Launcher-2.0.1-mac-x64.dmg` и `...-mac-arm64.dmg` — macOS,

   и выложит их в GitHub Release `v2.0.1`. Если версия не менялась, сборка
   пропускается — можно спокойно пушить правки сервера и кода.

**Обновление у игроков:**
- Windows — лаунчер сам находит новую версию, скачивает и ставит при перезапуске.
- macOS — приложение не подписано сертификатом Apple, поэтому автоматически
  обновиться не может: лаунчер показывает окно «Доступна новая версия» с кнопкой,
  которая открывает нужный .dmg в релизе.

**Первый запуск на macOS.** Приложение без подписи Apple, поэтому macOS может
написать «повреждено» или «не удаётся проверить разработчика». Решение — один раз
выполнить в Терминале:
```bash
xattr -cr "/Applications/Igrobar Launcher.app"
```
или: правый клик по приложению → «Открыть».

## Скины

- **Свой скин офлайн-профиля — без модов.** Лаунчер поднимает у себя локальный
  сервер скинов (`src/main/services/skinServer.js`, только 127.0.0.1) и запускает
  игру с authlib-injector, который спрашивает скин у этого сервера. Работает в
  любой версии, включая ванильные. Выключить: `"skin_server": false` в настройках.
- **Скины других игроков** — мод **CustomSkinLoader** (Modrinth), его лаунчер сам
  ставит в сборки с загрузчиком. Он берёт скины по нику с Mojang, Ely.by,
  TLauncher, LittleSkin. Если мод уже есть в модпаке или его поставил игрок,
  второй не ставится. Выключить: `"skin_mod": false`.
- Мод хранится отдельно от модпака (`instances\<сборка>\.igrobar-skinmod.json`),
  модпак его не удаляет и не дублирует. Класть его в `modpack.zip` не обязательно.
- «Каталог скинов» открывает сайт (MinecraftSkins.com, Ely.by, NameMC); кнопка
  «Скачать» на сайте сразу отдаёт скин в лаунчер. Список сайтов — `src/main/skinCatalog.js`.

## Где лежат данные

Две папки в `%APPDATA%` (macOS: `~/Library/Application Support`):

| Папка | Что там |
| --- | --- |
| `IBLauncher\versions`, `libraries`, `assets`, `runtime` | общие файлы игры — одна версия качается один раз для всех сборок |
| `IBLauncher\instances\<сборка>\` | папка называется по имени сборки (`Forge-1.12.2`, `Fabric-1.20.1`); у каждой сборки свои `mods`, `resourcepacks`, `shaderpacks`, `config`, `saves`, `options.txt` |
| `.LauncherIB\data\` | настройки, аккаунты (зашифрованы средствами системы), скины, журналы, кэш |
| `.LauncherIB\` | служебные файлы самого лаунчера (Electron) |

Старые папки `IgrobarLauncher` и `Igrobar Launcher` переносятся сюда сами при
первом запуске новой версии. Удаление сборки удаляет только её `instances\<сборка>`.
Папку игры можно перенести в «Настройках». Пути — в `src/main/paths.js`.

## Установка игры

- Новая сборка сразу начинает скачиваться. Пока она не установлена, вместо
  «Играть» показывается кнопка «Установить».
- Если часть файлов не скачалась (обрыв сети), лаунчер сам докачивает недостающее
  — до 4 попыток. Уже скачанное не теряется.

## Сервер IGROBAR: версия, NeoForge, адрес — `data/server_profiles.json`

Всё, что относится к серверу, лежит в одном файле **`data/server_profiles.json`**:

```json
"mc_version": "1.21.1",            ← версия Minecraft
"loader_type": "neoforge",          ← загрузчик: neoforge / forge / fabric / quilt
"loader_version": "21.1.265",      ← версия загрузчика
"server_address": "igrobar.aboba.host",  ← адрес, который попадёт в «Сетевую игру»
"modpack": { "repo": "mdreval/ib-launcher", "asset": "modpack.zip" }
```

**Как перевести сервер на новую версию** (например 1.21.4):
1. Поменяйте `mc_version` и `loader_version` в `data/server_profiles.json`.
2. Выложите новый `modpack.zip` под эту версию в релиз `mdreval/ib-launcher`.
3. Закоммитьте и отправьте на GitHub в ветку `main`:
   ```bash
   git add data/server_profiles.json
   git commit -m "Сервер: 1.21.4"
   git push
   ```
Новый релиз лаунчера для этого **не нужен**: лаунчер скачивает этот файл из
репозитория (`raw.githubusercontent.com/<репозиторий из package.json>/main/data/server_profiles.json`)
при запуске и перед каждым «Играть» в сборке IGROBAR. Сборка у игроков сама
переустановится под новую версию, модпак подтянется. Репозиторий должен быть
публичным (для приватного приложите `server_profiles.json` к релизу).

## Java

Ставить Java игрокам не нужно. Лаунчер сам скачивает официальную Java от Mojang
под каждую версию игры (в папку `runtime`): Java 8 для 1.16.5 и старше (1.12.2 и т.п.),
Java 17 для 1.18–1.20.4, Java 21 для 1.20.5 и новее. Скачивается один раз.

## Сеть

`src/main/core/netPatch.js` — повторы при обрывах, запасные адреса
(files.minecraftforge.net → maven.minecraftforge.net, launchermeta ↔ piston-meta)
и ограничение ожидания ответа 30 с, чтобы установка не висела.

## Модпак IGROBAR

> **Старый лаунчер (1.x).** Старый лаунчер берёт `modpack.zip` только из
> **самого последнего** релиза `mdreval/ib-launcher`. Чтобы у тех, кто ещё не
> перешёл на 2.0, модпак продолжал обновляться, прикладывайте `modpack.zip` к
> последнему релизу (в том числе к релизам нового лаунчера). Новому лаунчеру
> это не мешает: он ищет `modpack.zip` в любом из последних релизов.

- Источник — `modpack.zip` в релизах `mdreval/ib-launcher` (как в старом лаунчере).
  Берётся самый свежий релиз, в котором он есть.
- Работает только для сборок той версии, что указана в `data/server_profiles.json`, и только с включённой
  галочкой «Обновлять модпак» (у сборки IGROBAR она включена по умолчанию).
- Скачивание с докачкой после обрыва, проверка размера, распаковка во временную
  папку с проверкой контрольных сумм. Моды в сборке меняются только если весь
  архив распаковался без ошибок.
- Удаляются только моды, которые раньше поставил сам модпак. Ручные моды игрока
  не трогаются; выключенный мод модпака остаётся выключенным.

## Языки

Переводы — в `src/shared/i18n.js` (русский текст → украинский и английский).
Чтобы перевести новую строку интерфейса, достаточно добавить её туда.

## Оформление

- Темы: зелёная (по умолчанию) и красная IGROBAR. Цвета — в начале
  `src/renderer/css/base.css` (блоки `:root` и `:root[data-theme="red"]`).
- Картинки тем: `assets/ui/background.jpg`, `assets/ui/background-igrobar.jpg`,
  логотипы `assets/ui/logo.png`, `assets/ui/logo-red.png`.
- Своя картинка игрока хранится в `.LauncherIB\data\background\`.

## Готовые скины

`assets/skins/presets` (список в `presets.json`, названия на трёх языках).
